Designing for the
Autism Spectrum

A practical guide to building digital experiences that are predictable, calm, and genuinely accessible to autistic users.

Introduction

Context

Why this matters

Roughly 1–2% of the population is on the autism spectrum. That's tens of millions of people who use the web every day — for shopping, work, healthcare, communication.

Autism is a spectrum: a wide range of sensory sensitivities, processing styles, and communication preferences. There is no single "autistic user". But there are patterns — and patterns we can design for.

lightbulb The curb-cut effect: designing for the spectrum improves the experience for everyone — especially users who are tired, distracted, anxious, or new to the language.

Part I

Visual Principles

Typography, color, contrast, and spatial structure — the foundation of a calm, readable interface.

Visual · Typography

01 · Readable type

Typography that doesn't strain

text_fields

Body size 16–18px minimum, 18–20px for primary content

format_line_spacing

Line-height 1.5–1.7 — gives the eye space to rest

format_align_left

Left-align, never justify — justification creates uneven word gaps

font_download

Sans-serif or humanist serif — Atkinson Hyperlegible, Inter, Lora

straighten

Max line length 60–75 characters — easier to track

Pro tip: Atkinson Hyperlegible (designed by the Braille Institute) and OpenDyslexic are typefaces specifically engineered for legibility. Consider offering them as a user-selectable font option.

Avoid: ALL CAPS for body text, italics in long paragraphs, font weights below 400 at small sizes, decorative or display fonts for content.

Visual · Contrast

03 · Legibility

Contrast ratios

Contrast is non-negotiable. WCAG defines minimum ratios — but for autistic users you may want to aim higher than the minimum, without going to maximum.

Pure black on pure white (21:1) is technically perfect — but visually too harsh for many autistic readers. Aim for something between strong and screaming.

contrast

Target ratios

Body text (WCAG AA)4.5 : 1 min
Body text (sweet spot)7 : 1 to 12 : 1
Large text (≥18px)3 : 1 min
UI components3 : 1 min

Tools: WebAIM Contrast Checker · axe DevTools · Stark · Figma's built-in contrast indicator.

Visual · Layout

04 · Structure

Layout and spacing

Predictable structure reduces cognitive load. Autistic users often build mental maps of an interface — and surprises break that map.

The principle: if an element appears in the top-left on one page, it should be in the top-left on every page. Consistency is comfort.

space_bar

Generous whitespace — let content breathe; avoid dense layouts

format_indent_increase

Clear hierarchy — one idea per section, descriptive headings every 2–3 paragraphs

view_module

Chunked content — short sections beat one long wall of text

view_column

Single column for forms and reading — eyes move predictably top to bottom

Visual · Navigation

05 · Wayfinding

Predictable navigation

menu

Same nav, same place — across every page, every state

my_location

Show current location — breadcrumbs, aria-current="page", visible active state

linear_scale

Linear flows for tasks — multi-step forms with clear progress

map

Provide a sitemap — for users who prefer to see the full structure

tips_and_updates Pattern: "Where am I? Where can I go? How do I get back?" Every page should answer these three questions at a glance.

warning Avoid: mega-menus that change shape; navigation that hides on scroll; dropdown items that depend on hover; flyouts that disappear before you reach them.

Part II

Interaction & Motion

How content moves and how users move through it — the second half of comfortable design.

Interaction · Motion

06 · Animation

Motion — less is more

Motion captures attention involuntarily. For an autistic user, that means they can't focus on reading until the animation stops. The kindest motion is no motion — or motion the user controls.

timer_off

Short transitions — fade max 300ms, no bouncy easing

pause_circle

Pause control mandatory — for any animation longer than 5s

block

No parallax, no auto-scroll, no infinite loops

Always honor prefers-reduced-motion. The user's OS (macOS, Windows, iOS, Android) has this setting. Your CSS must respect it — non-negotiable.

@media (prefers-reduced-motion: reduce) {
  /* Remove all animations and transitions */
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
Interaction · Autoplay

07 · Surprise content

No autoplay, anywhere

videocam_off

Video autoplay

Hero videos that start playing on page load. Ad videos in articles. Sound on by default is hostile design.

view_carousel

Auto-rotating carousels

Sliders that change without user input. They're rarely read, frequently skipped, and create visual noise that competes for attention.

notifications_active

Surprise notifications

Pop-ups, toasts with sound, browser notifications requested on first visit. Every interruption is an attention tax.

play_circle Better pattern: show a poster image with a clear play button. The user decides when to engage. They get the same content — without ambush.

Interaction · Discoverability

08 · Visibility

No hidden interactions

If a feature exists, it should be visible. Autistic users rarely "explore" interfaces by hovering or guessing — that takes cognitive effort and risks unintended consequences.

touch_app

Hover-only menus that vanish on mobile

visibility_off

Swipe gestures with no visible alternative

keyboard_hide

Keyboard shortcuts that aren't documented in the UI

visibility Pattern to use: always provide a visible button or menu item for every action. Hover effects can enhance visibility, but never be the only way to reveal a feature.

accessibility_new Bonus: this also helps screen-reader users, keyboard-only users, motor-impaired users, mobile users — and your future tired self.

Interaction · Icons

09 · Symbols

Icons need words

Icons are visual shorthand — they only work if both designer and user share the same metaphor. For autistic users (and many others), abstract symbols can be ambiguous or stressful.

Rule: every icon gets a visible text label. Tooltips on hover are not enough.

What does this icon mean?

Part III

Language & Forms

How you write determines how easily users understand you — and how forgivingly they can recover from mistakes.

Language · Tone

10 · Plain language

Write directly, literally

Many autistic users process language literally. Idioms, sarcasm, and ambiguous phrasing can be confusing or anxiety-inducing.

format_clear

Short sentences — one idea per sentence; aim for 15–20 words

translate

Concrete words — "Click Submit" not "Let us know"

format_quote

No idioms, no sarcasm — "break the ice" reads as glass-shattering instructions

arrow_forward

Active voice — "We sent your order" beats "Your order has been sent"

menu_book Plain language standard: aim for CEFR B1 reading level (Flesch-Kincaid grade 7–8). Hemingway Editor and Grammarly can flag complex sentences.

Test it: read your microcopy aloud. If it sounds like a press release or ad copy, rewrite it in the way you'd explain to a friend.

Language · Errors

11 · Recovery

Error messages that help

Three rules for every error

closeVague: "Something went wrong."
checkSpecific: "We couldn't process your payment because the card number is invalid."
closeBlaming: "Invalid input."
checkHelpful: "Password must be at least 8 characters with one number."
closeAnonymous: "Error 503."
checkActionable: "Our servers are busy. Try again in a few minutes, or save your work as a draft."

construction Pattern: What happened · Why it happened · What to do next. Three sentences max.

Language · Forms

12 · Forms

Forms without anxiety

view_column

Single column — predictable top-to-bottom flow

label

Visible labels above fields — never placeholder-only

grid_view

Group related fields — <fieldset> + <legend>

help

Help text below the field — show format requirements before submission

timer_off

No time limits, or always extendable

Inline validation: validate as the user finishes a field (on blur), not on every keystroke. Constant red errors while typing feel like punishment.

Confirm-before-commit: for important actions (delete, submit, send), show a clear summary screen. Allow the user to go back and edit before final submission.

Avoid: CAPTCHA puzzles that demand pattern recognition under pressure; fields that auto-format while typing; required fields marked only with * in red.

Control · Personalization

13 · User control

Hand the controls to the user

The spectrum is wide. There's no single "perfect" interface for everyone. The best designs give users tools to adjust the experience to their own sensitivity.

"Don't decide what's comfortable for the user. Give them the means to decide for themselves." — A reasonable design principle
dark_mode

Light / dark mode toggle — visible, persistent, respect system default

format_size

Text scaling — full functionality at 200% zoom

animation

Reduce motion toggle — beyond just system pref

contrast

High-contrast mode as an opt-in

notifications_off

Notification controls — sounds, badges, frequency

Practice · Testing

14 · Validate

How to test your design

groups

Test with autistic users

Recruit through autism-led organizations (e.g. Autism Self-Advocacy Network). Pay testers fairly. Listen — don't defend.

extension

Use simulators

Browser DevTools: emulate vision deficiencies, slow CPU, reduced motion. Stark for color blindness. NoCoffee for visual impairments.

visibility

Cognitive walkthrough

For each task, ask: can the user predict what happens next? If not — there's friction. Document and redesign.

menu_book Reading-level tools: Hemingway Editor (en), Jasnopis (pl), readable.com — flag dense or complex passages in your microcopy and content.
